# GENOVA Studio — Mac Preview

The latest packaged app and ZIP archive are in `dist/20261118-214156/`. The app targets Apple Silicon and bundles its Java runtime; users do not need to install Java separately. Prefer the ZIP for transfer or archiving: its extracted app is checked with strict local code-signature verification. The frozen candidate ZIP passed the complete 543-check suite with its extracted bundled runtime; hashes, platform details, and logs are recorded in `validation/BUNDLED_RUNTIME_RELEASE_VALIDATION_2026-11-18.md`. This is a local preview, not a notarized public release. The file-sync service may attach Finder metadata to the `.app` copy inside this project folder, causing an in-place signature check to fail even though the ZIP's extracted app verifies.

Open `GENOVA Studio.app`, choose an analysis type, click **Example data**, then **Run analysis**. In urGENOVA, choose one of its six explicitly labeled designs first. The two-way mode also has a **Load empty-cell example** button. Alternatively, import CSV, TSV, or Excel `.xlsx`, or paste a long-format table. Each row is one observation.

The English interface presents all three families in one place. **GENOVA** handles the balanced scope below. **urGENOVA** has six independent Java G-study pilots: one-way random effects with unequal replicate counts nested within objects; two crossed random factors with unequal replicate counts nested within their cells (at most one empty cell); `(P:C) × (I:R)` with unequal nested group sizes (complete P × I table); crossed `P × I` with missing observations; `P × (I:H)` with missing observations; and matrix sampling `(P × I):R` with unequal P and I counts by R. All report ANOVA and raw variance components, but no D-study. **mGENOVA** has two limited multivariate random-effects G/D pilots: `P × I` and `P × (I:R)`. Persons are shared across fixed variables; the latter design also shares R groups across variables. **Export results (Excel)** writes typed numeric tables and metadata; GENOVA and mGENOVA also get a D-study sheet, while mGENOVA adds a typed D-study setup sheet for counts and weights. **Export table (CSV)** saves the selected table, and **Save report (TXT)** preserves detailed reports. See `UNIFIED_DESIGN.md` for validation status and the broader plan.

GENOVA scope: complete, balanced, univariate designs with a non-nested object of measurement, single-parent nesting or nesting chains, up to six dimensions and 30 D-study scenarios. D-studies for chains of two or more nesting levels are temporarily blocked; uncheck **Run D-study** to analyze these as G-studies while the independently observed discrepancy is investigated. The one-way urGENOVA pilot requires exactly three columns (object, nested replicate ID, score), at least two objects, and at least two unique observations per object. The two-way pilot requires exactly four columns (crossed random facet, object, cell-nested replicate ID, score), at least two levels of each crossed factor, positive residual degrees of freedom, and no more than one empty cell. The nested-cross pilot requires exactly five columns (object P, its containing group C, crossed group R, facet I nested within R, score); each P × I cell must occur once, with two or more P per C and I per R. The crossed missing-cell pilot requires exactly three columns (object P, facet I, score), one row per present cell, positive interaction degrees of freedom, and a connected P-I incidence graph. The nested missing-cell pilot requires exactly four columns (object P, group H, nested facet I, score), with at least two observed I levels in each P × H block. The matrix-sampling pilot requires exactly four columns (group R, object P, facet I, score), with a complete P × I table within each R. Absent rows, not zero scores, indicate missing data. All require finite scores, reject duplicate design cells, and retain negative variance estimates. Other unbalanced designs and all unbalanced D-studies are not implemented. Excel formulas must first be converted to values; `.xls` and automatic wide-to-long conversion are unsupported.

The mGENOVA `P × I` pilot requires exactly four columns (person, fixed variable, item, score). The `P × (I:R)` pilot requires five (person, fixed variable, R group, item nested in R and variable, score). Both require at least two persons and two fixed variables, complete person-by-item cells, and at least two items per nesting group. For `P × I`, optional D-study item counts are comma-separated in displayed variable order. For `P × (I:R)`, enter comma-separated R-group counts for each variable, with variable rows separated by semicolons (for example `3,6,3;4,3,3`). A blank D-study field uses observed counts. Universe weights `w` default to proportions of requested total item counts; estimation weights `a` default to `w`. Optional separate weight lists follow displayed variable order and are used as entered. When `a≠w`, composite relative/absolute outputs are mean-squared errors and composite G/Φ are not reported. These pilots match printed mGENOVA manual Appendices B/C/D results, including custom D-study counts and the unequal-weight Appendix D cases for `P × I`, but other multivariate designs are not implemented. The balanced engine is jGENOVA 1.0 by Joe E. Crick and Robert L. Brennan; its estimates and treatment of negative components remain unchanged. The urGENOVA pilots are new Java implementations of analogous ANOVA / Henderson Method 1 and reproduce the manual examples described in `UNIFIED_DESIGN.md`. The new pilots have **not** been compared with the original Windows executables. The original authors have not endorsed this GUI. Original downloaded distributions and statistical source code remain unchanged. Matching examples do not certify all designs.

Build from the project root with `python3 genova-gui/build.py --package`. It uses the installed Homebrew OpenJDK, or a JDK selected via `GENOVA_JDK`. Run `genova-gui/validate.py` with a Python environment containing `openpyxl`; the latest record is `validation/results.json`. The latest validation runs all 543 checks with both the development JDK and the candidate ZIP's extracted bundled runtime. It verifies GENOVA, the D-study grid and PNG surface rendering, all six urGENOVA pilots, both mGENOVA pilots (including independent synthetic cases and unequal-weight MSEs), and Excel exports; compares the original GENOVA full report except date/newlines; and confirms 95 original file hashes are unchanged. It includes a published balanced `P × I × J` raw-data benchmark; see `validation/gleser1965/README.md`. The build verifies the ZIP after extraction, including its local code signature. The app has not been Apple-notarized.

The **D-study heatmap** tab is available after a balanced GENOVA D-study with exactly two random facets besides the object of measurement. Set the two count ranges (up to 30 grid cells), choose Phi or G coefficient for color, hover over a cell for both exact values, and export the grid as CSV. A nested facet's count is the number of levels per parent group. Every grid point is computed by the original jGENOVA engine. The official nested example's overlapping G and Phi scenarios were checked against the existing D-study table.

The **3D plot** tab uses the same calculated grid. Choose Phi or G coefficient for height and color, drag the plot or use the rotate/tilt sliders, inspect exact values at computed points, and export a 1600×1000 PNG. The surface between points is bilinear visual interpolation; no additional statistical scenarios are inferred. Height follows the coefficient axis, while the color bar spans the displayed grid values. A preview PNG for the official nested example is in `dist/20261009-103626/dstudy_surface_phi.png`.

`build/latest.json` identifies the latest JAR and app. Intermediate builds remain in `build/` and `dist/`; original materials are outside those folders. Follow the five-hour usage rule in the root `AGENTS.md` during future development.
